# نقشه راه توسعه

## انجام‌شده

### فاز 0: آماده‌سازی پروژه

- ایجاد Solution و Worker Service با C#
- ایجاد پوشه `docs`
- اتصال پروژه به GitHub
- تعریف تنظیمات پایه و متغیرهای محیطی

### فاز 0.1: Scheduler اولیه

- ایجاد `SchedulerAgent`
- خواندن ساعت اجرا و timezone از تنظیمات
- اجرای روزانه بدون دیتابیس، lock و retry پیشرفته
- اضافه‌کردن اجرای دستی با `run-once`

### فاز 1: تولید محتوا

- تولید مقاله از روی فایل پرامپت
- تولید خلاصه مناسب شبکه‌های اجتماعی
- تولید تصویر شاخص
- انتقال پرامپت مقاله و تصویر به فایل‌های قابل ویرایش
- اضافه‌کردن fixture برای تست بدون API

### فاز 2: انتشار

- انتشار مقاله در WordPress REST API
- آپلود تصویر در Media Library
- تنظیم featured media و درج تصویر در متن
- انتشار پست تصویری در Instagram Graph API
- انتشار پیام در Telegram channel
- پشتیبانی از ارسال تلگرام با تصویر و بدون تصویر

### فاز 3: بهبود وردپرس و سئو

- اعتبارسنجی اتصال وردپرس
- اعتبارسنجی دسته‌بندی قبل و بعد از publish
- حذف placeholderهای citation خراب
- اضافه‌کردن alt text، caption تصویر، excerpt و لینک‌های داخلی
- امکان ارسال metaهای Yoast در صورت فعال‌سازی REST meta در وردپرس

### فاز 4: Provider architecture

- تعریف `ILlmProvider`
- تعریف `IImageProvider`
- پیاده‌سازی Providerهای `OpenAI`، `Groq`، `Fixture` و `None`
- پرامپت اختصاصی برای Groq
- جداکردن تنظیمات هر Provider

### فاز 5: Groq hardening

- جداسازی research و writing
- استفاده از `groq/compound-mini` برای research
- استفاده از `openai/gpt-oss-120b` از طریق Groq برای writing
- کاهش اندازه prompt research برای جلوگیری از 413
- اضافه‌کردن fallback writer برای خطای JSON
- اضافه‌کردن حداقل طول مقاله

### فاز 6: استقرار

- Dockerfile
- `compose.yaml`
- `.env.example`
- راهنمای Docker
- راهنمای فارسی قدم‌به‌قدم انتقال به سرور

## در حال تکمیل

- به‌روزرسانی مستندات با وضعیت واقعی پروژه
- تنظیم بهتر promptها برای جلوگیری از مقاله‌های تکراری
- پایدارسازی کیفیت خروجی Groq و OpenAI

## فازهای پیشنهادی بعدی

### فاز 7: دیتابیس و تاریخچه اجرا

- ثبت هر اجرای job
- ذخیره عنوان، منابع، Provider، وضعیت انتشار و خطاها
- جلوگیری از تکرار موضوع و منبع
- امکان ادامه یا retry بعد از خطا

### فاز 8: بازبینی انسانی

- انتشار اولیه به‌صورت draft در وردپرس
- ارسال لینک preview به تلگرام یا پنل داخلی
- publish نهایی بعد از تأیید
- امکان رد یا اصلاح مقاله

### فاز 9: پنل مدیریت

- مشاهده آخرین اجراها
- مشاهده خطاها
- اجرای دستی job
- تغییر prompt فعال
- فعال/غیرفعال کردن کانال‌های انتشار

### فاز 10: کیفیت محتوا و ضدتکرار

- محاسبه similarity با مقاله‌های قبلی
- نگهداری لیست موضوعات ممنوع و موضوعات اخیر
- کنترل منابع تکراری
- اعتبارسنجی لینک منابع

### فاز 11: مانیتورینگ production

- health check
- log rotation
- اعلان خطا در تلگرام
- گزارش روزانه وضعیت اجرا
- ثبت مصرف API و هزینه تقریبی

### فاز 12: توسعه کانال‌ها و رسانه

- بهبود مسیر اینستاگرام و قالب‌های تصویری
- امکان تولید چند قالب تصویر
- بررسی انتشار در LinkedIn یا X
- بررسی تولید ویدئو کوتاه در فازهای بعدی

## تصمیم‌های فنی باز

- انتخاب دیتابیس: SQLite برای شروع یا PostgreSQL برای production
- روش جلوگیری از تکرار: similarity ساده، embedding یا ترکیب هر دو
- مدل workflow: اجرای خطی فعلی یا job queue
- سطح دخالت انسانی: draft-only، approval اجباری یا publish مستقیم
- ابزار مانیتورینگ و alerting
