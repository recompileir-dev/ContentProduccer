# معماری پیشنهادی

## نمای کلی

سامانه بهتر است به‌صورت ماژولار طراحی شود تا تولید محتوا، کنترل کیفیت و انتشار به پلتفرم‌ها از یکدیگر جدا باشند.

## معماری نسخه اولیه

نسخه اولیه با حداقل نیازها پیاده‌سازی می‌شود:

- یک Worker Service با زبان C#
- یک `SchedulerAgent` دائماً در حال اجرا
- اجرای روزانه سرویس تولید محتوا در ساعت تنظیم‌شده
- تنظیم ساعت و منطقه زمانی از طریق `appsettings.json`
- بدون دیتابیس، قفل توزیع‌شده، صف، Retry و پکیج زمان‌بندی خارجی

در این نسخه فرض می‌شود فقط یک نمونه از برنامه اجرا خواهد شد.

```text
Content Sources / Topics
          |
          v
     Scheduler / Jobs
          |
          v
   Content Orchestrator
      |      |      |
      v      v      v
 Research   AI    Media
      |   Generation |
      +------|-------+
             v
      Quality Checks
             |
             v
       Review / Approval
          |         |
          v         v
     WordPress   Instagram
          \         /
           v       v
        Logs & Status
```

## اجزای اصلی

### 1. زمان‌بند و صف کارها

وظیفه زمان‌بند ایجاد کارهای روزانه و اجرای فرایند تولید محتوا است. استفاده از صف کار باعث می‌شود خطاهای موقت، تلاش مجدد و اجرای مستقل مراحل ساده‌تر شود.

### 2. هماهنگ‌کننده محتوا

هماهنگ‌کننده وضعیت هر محتوا را مدیریت می‌کند و مراحل تحقیق، تولید، کنترل کیفیت، تأیید و انتشار را به ترتیب اجرا می‌کند.

### 3. سرویس تولید با هوش مصنوعی

این بخش با توجه به موضوع، لحن برند، قالب محتوا و کانال مقصد، خروجی مناسب تولید می‌کند. پرامپت‌ها باید نسخه‌بندی شوند تا تغییر کیفیت خروجی قابل بررسی باشد.

### 4. کنترل کیفیت

پیش از انتشار، قواعدی مانند طول متن، وجود عنوان، تکراری نبودن، وجود منابع، کلمات ممنوع، ساختار هشتگ‌ها و محدودیت‌های هر کانال بررسی می‌شوند.

### 5. پنل بازبینی و تأیید

در نسخه اولیه، محتوا باید پیش از انتشار توسط مدیر محتوا تأیید یا رد شود. وضعیت‌ها و تغییرات باید ثبت شوند.

### 6. اتصال وردپرس

انتشار مقاله، دسته‌بندی، برچسب، تصویر شاخص و وضعیت نوشته از طریق WordPress REST API انجام می‌شود.

### 7. اتصال اینستاگرام

انتشار تصویر و کپشن از طریق Instagram Graph API انجام می‌شود. حساب اینستاگرام باید شرایط لازم برای استفاده از API رسمی متا را داشته باشد.

### 8. ذخیره‌سازی و لاگ

اطلاعات محتوا، وضعیت مراحل، شناسه انتشار در پلتفرم‌ها، خطاها و مصرف سرویس‌های هوش مصنوعی باید ذخیره شوند.

## مدل داده پیشنهادی

- `ContentItem`: موضوع، عنوان، متن اصلی، وضعیت، زمان انتشار
- `ChannelContent`: نسخه مخصوص هر کانال، کپشن، هشتگ و تنظیمات انتشار
- `MediaAsset`: تصویر، توضیح جایگزین، منبع و وضعیت آماده‌سازی
- `Publication`: کانال، شناسه خارجی، زمان انتشار و نتیجه
- `PromptTemplate`: متن پرامپت، نسخه و کاربرد
- `JobRun`: مرحله اجرا، زمان شروع و پایان، خطا و تعداد تلاش
- `AuditLog`: تغییرات کاربر یا سیستم روی محتوا
